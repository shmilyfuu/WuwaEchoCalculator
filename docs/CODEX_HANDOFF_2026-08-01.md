## 3. 最终选择的计分方式

最终采用此前两套方案中的 **方案A**。

方案A的处理规则：

- 生命、生命百分比、防御、防御百分比按低档正向加分。
- 暴击、暴击伤害、攻击、攻击百分比按高档扣分。
- 共鸣效率、普攻伤害加成、重击伤害加成、共鸣技能伤害加成、共鸣解放伤害加成统一记0分。
- 界面不显示“方案A”字样。
- 界面不提供方案切换。
- 方案B停止使用。

这是反向计分活动。较差的辅音属性会增加分数，较强的输出属性会扣分。最终排名按分数从高到低排列。

### 3.1 最终成绩公式

每个声骸有5条辅音属性。

```text
单件声骸小计 = 5条辅音属性分数相加
原始总分 = 5件声骸小计相加
最终平均分 = 原始总分 ÷ 5
```

最终平均分保留1位小数。排名计算建议直接比较原始总分整数，显示时再除以5，可避免浮点误差。屏幕上应同时显示原始总分和最终平均分。

### 3.2 同分处理

最终平均分相同时，按照以下顺序继续比较：

1. 正分词条数量。
2. `+10` 分词条数量。

两项仍相同时，按“规则未覆盖的异常状况以主播说明为准”处理。

### 3.3 预测分规则

活动存在“神预言”预测规则：

```text
|预测分 - 实际最终平均分| <= 5
```

满足条件视为押中。

该功能当前从计算器界面移除。后续除非用户重新提出需求，计算器无需显示预测分、押中结果或相关输入框。

## 6. 声骸计算器的产品需求

### 6.1 产品形态

- Windows 独立应用。
- WebView2 外壳。
- 便携式压缩包，完整解压后双击 EXE 使用。
- 无需浏览器扩展。
- 模型与运行文件随应用携带。
- 图片只在本机处理。
- 断网后仍可识别。
- 应用数据写入程序目录下的 `data/WebView2`。

### 6.2 图片输入

必须支持：

- 点击上传。
- 拖拽图片。
- `Ctrl+V` 粘贴剪贴板截图。
- 随机截图边界。
- 不同截图尺寸。
- 已裁到声骸面板的截图。
- 画面中完整显示5条辅音属性。

程序读取整张截图。用户无需选择“右侧60%”“右侧75%”或固定裁切区域。

### 6.3 OCR目标

程序需要忽略：

- 声骸名称。
- COST。
- 等级。
- 两条主音属性。
- 界面按钮和图标。

程序只输出底部5条辅音属性。

示例回归用例：

```text
暴击伤害 15.0%  -> -1
防御百分比 10.9% -> +2
暴击 9.3%       -> -5
防御 60         -> +3
生命 320        -> +10
单件小计         -> 9
```

截图上方的 `暴击伤害 44.0%` 和 `攻击 150` 属于主音属性，必须排除。

### 6.4 OCR识别策略

当前方案使用本地 PaddleOCR.js 与 PP-OCRv5 移动端模型。

识别链路：

```text
导入整张截图
→ 等比例放大并增加边缘留白
→ PP-OCRv5 检测文字框
→ PP-OCRv5 识别文字
→ 按纵坐标组合同行文字
→ 匹配13类合法辅音属性
→ 根据百分号区分固定值与百分比值
→ 使用合法档位严格校验
→ 排除主音属性
→ 根据置信度、纵向连续性和属性唯一性选择5行
→ 填入下拉框
```

当前13类属性：

1. 生命
2. 生命百分比
3. 攻击
4. 攻击百分比
5. 防御
6. 防御百分比
7. 暴击
8. 暴击伤害
9. 共鸣效率
10. 普攻伤害加成
11. 重击伤害加成
12. 共鸣技能伤害加成
13. 共鸣解放伤害加成

识别结果必须经过合法档位校验。模型读到 `44.0%`、`150` 或不存在的辅音档位时，不应强制吸附到最近档位。

### 6.5 人工修正

每一行都包含：

- 属性下拉框。
- 档位下拉框。
- 单条分数。
- 状态圆点。

属性改变后，档位下拉框只展示该属性的合法档位。

状态圆点：

- 绿色：可信度高。
- 黄色：建议核对。
- 红色：手动选择或识别缺失。

界面不显示置信度百分比。

### 6.6 五件声骸记录

用户确认前选择记录位置：

- 声骸1
- 声骸2
- 声骸3
- 声骸4
- 声骸5

确认记录后，每张卡片保存：

- 5条辅音属性名称。
- 5个档位数值。
- 5条单项分数。
- 单件声骸小计。

五张卡需要在同一屏完整显示。已记录卡支持编辑和删除。点击编辑后，中央下拉框重新载入该件记录。

### 6.7 总分与导出

统计区域显示：

- 已记录数量。
- 原始总分。
- 最终平均分。

五件未录满时，最终平均分显示 `—`。

五件录满后启用导出按钮。导出的 PNG 需要包含：

- 五张声骸记录卡。
- 每件5条辅音属性。
- 每条属性的档位与分数。
- 每件小计。
- 原始总分。
- 最终平均分。
- 导出时间。

### 6.8 识别控制

图片区域下方只保留：

- 停止识别。
- 重新识别。

点击“停止识别”后立即终止当前 OCR 任务。当前实现通过重载隐藏 OCR iframe 释放推理环境，随后重新初始化模型。原截图继续保留。

### 6.9 界面要求

- 深色配色接近 Windows 11 默认界面。
- 正分使用绿色。
- 扣分使用红色。
- 存疑状态使用黄色。
- 主操作使用 Windows 蓝色强调色。
- 默认窗口尺寸为 `1280×760`。
- 最小窗口尺寸为 `1280×760`。
- 应用打开时直接使用最小尺寸。
- 最小尺寸下无页面滚动条。
- 窗口允许放大。
- 所有按钮文字水平与垂直居中。
- 同一行按钮高度、顶边和底边对齐。
- 各卡片内边距与卡片间距统一。
- 所有普通状态、识别进度和简化错误统一显示在底部状态栏。
- 技术错误详情保留在“OCR明细”。
- 图片区域不再单独显示“尚未导入图片”文字。
- 顶部不再单独显示识别成功或识别失败标签。
- 保留窗口置顶开关。
- 保留应用图标。

- `@paddleocr/paddleocr-js` 0.4.2。
- `onnxruntime-web` 1.24.x。
- PP-OCRv5 mobile detection。
- PP-OCRv5 mobile recognition。
- WASM后端。
- OCR运行于隐藏 iframe。

## 11. 当前已知风险

### 11.1 v1.2.1尚未实机确认

Actions只验证构建和文件存在。WebView2实际加载、PaddleOCR推理和停止识别需要Windows电脑测试。

### 11.2 ONNX Runtime文件组合

当前错误来自缺少原名模块。后续升级 `onnxruntime-web` 时，文件名和加载方式可能变化。升级依赖后必须检查 `public/assets` 与运行时请求路径。

### 11.3 OCR耗时

PP-OCRv5首次加载模型会占用时间。小图预处理会放大，检测边长当前配置为1600。低配置电脑可能出现较长等待，需要实测后调整。

### 11.4 初始红色状态

空白下拉行当前可能直接显示红色圆点和红色边框。该视觉会让初始界面看起来像报错。可考虑增加“未开始”灰色状态，导入图片或用户尝试确认后再显示红色。

### 11.5 状态兼容桥

v1.2.1使用兼容桥把旧状态函数映射到新的底部状态栏。整理代码后应删除兼容层，避免状态来源分散。

### 11.6 活动规则尚待补齐的文案字段

以下信息未在本次对话里确定具体值：

- 企鹅群号或二维码。
- 活动预计结束时间。
- 最终发布动态使用的具体活动图片。
- 同分比较两项后仍相同的处理细则。
- “神预言”称号的具体发放形式。

这些字段由主播发布前补充。
