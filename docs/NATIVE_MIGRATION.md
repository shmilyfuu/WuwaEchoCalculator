# Direct2D 原生迁移记录

分支：`feature/native-direct2d-migration`

草稿 PR：#6

此分支用于验证取消 WebView2 后的界面还原、原生 OCR 与导出能力。`main` 保持现状，原生版完成实机校准前不合并。

## 当前实现

- Win32 原生固定窗口，客户区为 `1188 × 772` DIP。
- Direct2D 绘制背景、面板、按钮、记录卡、下拉列表和弹窗。
- DirectWrite 绘制中文与数字。
- WIC 读取本地图片、剪贴板位图并生成 PNG 记录图。
- 支持点击选择图片、文件拖入和 `Ctrl+V` 粘贴截图。
- 支持五行属性与档位的自动识别和手动选择。
- 支持计分、记录、覆盖、编辑、删除和清空。
- 五张记录卡全部写入后，导出按钮才恢复可用状态。
- 导出标题使用 Direct2D 外观叠加 Win32 `EDIT`，保留中文输入法、光标与文本选择。

## 本轮故障修复

### OCR 全部为空

PP-OCRv5 识别模型返回的张量已经是归一化概率。首轮原生代码再次执行 Softmax，置信度被压低到接近 `1 / 字符类别数`，所有文字行随后被阈值过滤。

当前修正：

- 自动判断识别张量是否已归一化。
- 已归一化时直接使用最大类别概率。
- 原始 logits 才执行 Softmax。
- 检测最长边改为 `1280`。
- 检测阈值改为 `0.25`。
- 文字框阈值改为 `0.32`。
- 增加文字框外扩范围。
- 识别阈值改为 `0.20`。
- 未检测到文字区域、检测到区域但识别为空时显示不同错误。

构建自测使用五组中文声骸属性，成功识别 11 条文字：标题、五个属性名和五个数值。

### 导出输入框

- 真实输入控件缩进到 Direct2D 圆角外框内部。
- 输入控件字号改为 13 DIP。
- 弹窗先完成 Direct2D 绘制，再显示并刷新真实输入控件。
- 圆角、描边和蓝色底线继续由 Direct2D 绘制。

### PNG 未生成

- WIC 编码前增加显式像素格式转换。
- 逐步检查流、编码器、帧、像素格式、写入与提交结果。
- 保存失败时在状态栏显示具体失败环节。
- 编码结束后检查目标文件是否真实存在。
- GitHub Actions 增加 Direct2D + WIC PNG 落盘自测，要求生成文件大于 1 KB。

## 自动验证

每次构建均执行：

1. MSVC 编译原生应用。
2. PP-OCRv5 检测与识别实际推理。
3. 校验至少识别三条文字。
4. Direct2D 绘制 WIC 位图。
5. WIC 编码并生成 PNG 文件。
6. 校验 PNG 文件存在且大小正常。
7. 通过后才生成测试压缩包。

## 按钮交互规范

所有按钮保持普通箭头光标。

蓝色按钮：

- 默认：`#4CC2FF`
- Hover：`#AFE6FF`
- 按下：`#0078D4`

灰色按钮使用白色透明层叠加 `#202020` 背景：

- 默认：白色 6%
- Hover：白色 8%
- 按下：白色 4%

红色按钮统一使用 `#C42B1C`：

- 默认：50%
- Hover：70%
- 按下：90%

按下状态将按钮内容整体下移 1 DIP。

## 当前限制

- OCR 文字框仍采用轴对齐连通区域，复杂透视或倾斜截图可能需要继续优化。
- 五条属性的同行组合与错字别名仍需使用真实游戏截图扩充回归样本。
- 记录和置顶状态尚未写入本地文件。
- 下拉列表键盘导航仍待补齐。
- WebP 是否可直接读取取决于系统 WIC 编解码器。

## 推荐测试顺序

1. 使用正式版能够正确识别的同一张游戏截图。
2. 核对五个属性名称和五个数值。
3. 测试停止识别和重新识别。
4. 填满五张记录卡并打开导出弹窗。
5. 测试空标题、中文标题、英文标题和超长标题。
6. 选择保存路径后确认 PNG 文件真实生成。
7. 若导出失败，记录状态栏显示的具体错误文本。
8. 在 100%、125%、150% 显示缩放下检查输入框位置。
