# Direct2D 原生迁移记录

分支：`feature/native-direct2d-migration`

草稿 PR：#6

此分支用于验证取消 WebView2 后的界面还原与交互实现。`main` 保持现状，原生预览完成实机校准前不合并。

## 当前实现

- Win32 原生固定窗口，客户区为 `1188 × 772` DIP。
- Direct2D 绘制背景、面板、按钮、记录卡、下拉列表和弹窗。
- DirectWrite 绘制中文与数字。
- WIC 读取本地图片、剪贴板位图并生成 PNG 记录图。
- 支持点击选择图片、文件拖入和 `Ctrl+V` 粘贴截图。
- 支持五行属性与档位的手动选择。
- 支持计分、记录、覆盖、编辑、删除和清空。
- 五张记录卡全部写入后，导出按钮才恢复可用状态。
- 导出标题使用 Direct2D 绘制外观，再叠加透明 Win32 `EDIT` 控件，保留中文输入法、光标和文本选择。

## 按钮交互规范

所有按钮保持普通箭头光标，鼠标经过时不切换为手形。

蓝色按钮：

- 默认：`#4CC2FF`
- Hover：`#AFE6FF`
- 按下：`#0078D4`

灰色按钮使用白色透明层叠加 `#202020` 背景：

- 默认：白色 6%
- Hover：白色 8%
- 按下：白色 4%

红色按钮统一使用 `#C42B1C`：

- 默认：50%
- Hover：70%
- 按下：90%

按下状态将按钮内容整体下移 1 DIP，形成轻微下压反馈。

## 当前限制

- PP-OCRv5 尚未迁移到 ONNX Runtime C++。
- “停止识别”按钮暂时禁用。
- “重新识别”只提示 OCR 尚未接入。
- 记录和置顶状态尚未写入本地文件。
- 下拉列表已支持鼠标滚轮，键盘导航仍待补齐。
- WebP 是否可直接读取取决于系统 WIC 编解码器，后续需要内置解码方案。
- 当前布局按原 CSS 坐标初步翻译，仍需在 100%、125%、150% DPI 下截图叠加校准。

## 推荐测试顺序

1. 启动后确认窗口客户区、标题栏和整体布局。
2. 检查所有按钮的默认、Hover、按下颜色与 1 DIP 下压反馈。
3. 检查按钮区域的鼠标始终保持箭头。
4. 通过点击、拖入和 `Ctrl+V` 测试图片预览。
5. 手动填写五条互不重复的属性与档位。
6. 分别记录到声骸 1—5，确认导出按钮从禁用变为可用。
7. 点击导出记录，测试中文输入、长度提示、回车确认与 Esc 取消。
8. 导出 PNG，核对五张卡、总分、平均分和自定义标题。
9. 测试覆盖、编辑、删除与清空确认弹窗。
10. 在 100%、125%、150% 显示缩放下分别截图。
