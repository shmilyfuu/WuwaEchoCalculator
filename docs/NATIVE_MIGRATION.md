分支：`feature/native-direct2d-migration`

草稿 PR：#6

该分支继续保持独立，`main` 未产生本次迁移提交。当前版本已经通过 Windows MSVC 编译、打包与 GitHub Actions 上传检查。

## 当前实现

- Win32、Direct2D、DirectWrite、WIC 原生界面。
- 固定 `1188 × 772` 客户区域。
- 点击选择图片、文件拖入、`Ctrl+V` 粘贴。
- 手动选择五条属性与档位。
- 计分、记录、覆盖、编辑、删除、清空。
- 五件记录完整后启用 PNG 导出。
- Direct2D 外观叠加 Win32 `EDIT` 的导出标题输入框。
- 按钮普通箭头光标、悬停色、按下色与 1 DIP 下压反馈。
- 使用正式版对应的下拉箭头、词条星形与三种识别状态图标。
- 当前统计区域、置顶开关及其点击区域已重新校准。
- 弹窗上下分区改为无透明度重复叠加的拼接方式。
- 导出输入框恢复占位文字和常驻长度提示。

## 原生 OCR 试验

- ONNX Runtime C++。
- PP-OCRv5 移动端文字检测模型。
- PP-OCRv5 移动端文字识别模型。
- 模型和字符表随预览包放入 `models` 目录。
- 导入图片后在后台线程自动识别。
- 支持停止当前识别与重新识别。
- 检测结果按纵向位置分组，再匹配声骸属性名称和对应档位。
- 高置信结果显示绿色图标，低置信结果显示黄色图标，手动修改后显示粉色图标。

首轮检测后处理采用轴对齐连通区域，主要面向游戏界面内水平排列的属性文字。复杂透视、旋转、过度裁切和背景干扰可能产生漏识别，需要通过实机截图继续调整阈值与区域合并逻辑。

## 测试重点

1. 100% Windows 显示缩放下检查统计区域和置顶开关位置。
2. 打开清空、删除、覆盖与导出弹窗，检查分区交界处是否仍有亮带。
3. 在导出标题中输入中文、英文和数字，检查文字、光标、选区和占位提示。
4. 导入正式游戏声骸截图，记录 OCR 识别条数、错误属性和错误档位。
5. 识别期间点击停止，随后点击重新识别。
6. 125% 和 150% 显示缩放下检查图标和真实输入框的位置。
